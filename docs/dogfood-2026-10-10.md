## Runs

1. **HM driver** (`scripts/dogfood/hm-run.sh`) — a small
   Hindley–Milner-flavoured expression language: scaffold → register
   6 modules → write_module ×7 (library + test/Spec.hs) → project
   gate → eval flat + nested → 3 properties persisted. Sources live
   inline in `hm-loop.py` (single source of truth: write_module ships
   exactly those bytes). `hm-run.sh` chains three green blocks:
   warning-failing local compile with the scaffold's exact stanza
   flags + 3×300 QuickCheck → fresh-binary probe → the MCP-only loop
   under hangwatch.
2. **Small driver** (`scripts/dogfood/ar-run.sh`) — a third of the
   surface (3 modules, 2 properties) proving the loop is not
   HM-shaped. Shares `dogfood-local-check.sh`.
3. **Real agent** (`scripts/dogfood/agent-run.sh`) — opencode (GLM)
   given only the task text; it followed the create → register →
   write → gate → property loop from the tool instructions alone,
   recovering from 7 clean error envelopes with zero unknown-tool
   calls. Scoring is mechanical: the server's `tool_call_*` events
   (stderr tee via `agent-server-shim.sh`), the property store, and
   the process table (`agent-score.sh`, baseline-subtracted).

## Zombie accounting

The committed drivers' teardowns report 0 leftover servers. Five
daemon+server pairs found during W3.3 were debris from interrupted
MANUAL debug iterations earlier the same day (ad-hoc spools under
/tmp), not from the committed scripts; they were killed and
`agent-score.sh` now subtracts a pre-run baseline so foreign debris
can never taint a verdict.
